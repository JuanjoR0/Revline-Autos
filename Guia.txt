--- PASO 1 (creacionde proyecto carpetas paquetes y dependencias ) ---

1. hemos ejecutado en consola en la raiz del proyecto los comandos para crear las carpetas (mkdir backend, mkdir frontend , mkdir docs)
2. creamos el entorno virtual de python donde se van a instalar las dependencias del proyecto (python -m venv venv) 
3. activamos el entorno de python (venv\Scripts\activate)
4. Instalar los paquetes necesarios para Django y Render (pip install django djangorestframework djangorestframework-simplejwt django-cors-headers dj-database-url psycopg2-binary pillow gunicorn whitenoise)
    - django (paquete principal del framework)
    - djangorestframework (sirve para ampliar Django para crear APIs RESTful, es decir, endpoints que devuelven y reciben datos en formato JSON.)
        - Expondrá los endpoints /api/vehicles/, /api/orders/, etc.
        - Gestionará los serializers y viewsets para enviar los datos al frontend React.
    - djangorestframework-simplejwt (Extensión de DRF que añade autenticación por tokens JWT (JSON Web Token). Permite manejar login/registro de usuarios sin sesiones ni cookies (más seguro y moderno).)
        - Usarás /api/auth/token/ y /api/auth/token/refresh/
        - Los usuarios se loguean y obtienen un token para autenticar peticiones.
    - django-cors-headers (Permite que el frontend (React) pueda comunicarse con el backend (Django) aunque estén en diferentes puertos o dominios durante el desarrollo.)
        - React (Vite) corre en http://localhost:5173
        - Django en http://localhost:8000
    - dj-database-url (Simplifica la configuración de la base de datos leyendo la URL desde una variable de entorno (por ejemplo, la que te da Render).)
        - En local: usa SQLite
        - En Render: leerá DATABASE_URL (de PostgreSQL) automáticamente.
    - psycopg2-binary (Es el driver de conexión de Python con PostgreSQL.Render usa PostgreSQL, así que este paquete permite que Django se conecte correctamente a esa base de datos.)
        - SQLite no lo necesita, pero lo incluimos desde el principio para el despliegue en render que si lo necesita.
    - pillow (Librería para manipular imágenes (leer, redimensionar, guardar, etc.). Django la necesita si usas campos ImageField en tus modelos (como Vehicle.image).)
    - gunicorn (Servidor web de producción para ejecutar Django en render (en lugar del servidor de desarrollo del local). Render lo usa para lanzar la aplicación real.)
    - whitenoise (Sirve para servir archivos estáticos (CSS, JS, imágenes del frontend) directamente desde Django en producción, sin usar un servidor externo)
        - Django servirá el build del React (SPA) directamente desde /frontend_dist.
    
    (Los tendremos todos registrados en el requirements.txt)
5. Generar un listado exacto de todas las dependencias instaladas y sus versiones (pip install -r requirements.txt)
6. nos movemos al back (cd backend) y creamos el proyecto principal de Django (django-admin startproject backend .)
7. creamos la aplicacion principal donde irá toda la lógica del negocio (python manage.py startapp tienda). Esta app gestionará los modelos, vistas y endpoints del backend (vehículos, pedidos, usuarios, etc.)

--- PASO 5 (Serializers y Views "La API REST") ---

21. Creamos los serializers en el archivo tienda/serializers.py que tambien debemos crearlo, Los serializers sirven para convertir datos complejos de Python (como modelos, objetos, listas, relaciones, etc.) en JSON, y también para hacer lo inverso, convertir JSON en objetos de Python y luego en base de datos.
        -El backend Django trabaja con objetos de python y bases de datos
        -El frontend React trabaja con JSON, que se envía y recibe por HTTP (REST API).
                -UsuarioSerializer:	Devuelve datos de usuario sin incluir contraseña.
                -RegistroUsuarioSerializer:	Crea nuevos usuarios (registro).
                -VehiculoSerializer:	Convierte vehículos en JSON (y viceversa).
                -DetallePedidoSerializer:	Muestra cada producto dentro de un pedido (incluye su vehiculo).
                -PedidoSerializer:	Incluye el pedido y su array de detalles. También crea el pedido con todos sus ítems.
22. Creamos en tienda/views.py las vistas o endpoints de la API, que son las funciones o clases que reciben las peticiones (GET, POST, PUT, DELETE, etc.), las procesan, y devuelven una respuesta JSON.
        -RegistroUsuarioView: Permite al usuario registrarse (crear cuenta).Usa el serializer RegistroUsuarioSerializer para validar y crear el usuario. (AllowAny)
        -VehiculoViewSet: Proporciona todas las operaciones CRUD para vehículos. Usa el serializer VehiculoSerializer
                -GET /api/vehiculos/ → listar         (AllowAny)
                -POST /api/vehiculos/ → crear         (IsAdminUser)
                -PUT /api/vehiculos/1/ → actualizar   (IsAdminUser)
                -DELETE /api/vehiculos/1/ → borrar    (IsAdminUser)
        -PedidoViewSet: Gestiona los pedidos ver, crear, modificar, eliminar.Usa el serializer PedidoSerializer.   (IsAuthenticated)
                -Método get_queryset(self): Si el usuario es administrador → ve todos los pedidos. Si es cliente → ve solo los suyos.
                -Método perform_create(self, serializer): Cada vez que se crea un pedido (POST), Django añade automáticamente el usuario que lo ha creado (self.request.user).
